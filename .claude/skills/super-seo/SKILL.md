# Super SEO — оркестратор

## Как это работает

Один вход, веерный запуск подпроверок, единая приоритизация на выходе.
Каждая рекомендация обязана нести четыре вещи, иначе она не попадает в отчёт:

1. **Наблюдение** — что именно измерено (URL, селектор, число).
2. **Зависимость** — что нужно сделать раньше (нет смысла в семантике, если сайт не индексируется).
3. **Фальсификация** — «как мы узнаем, что это не сработало».
4. **Опережающий индикатор** — что сдвинется через 1–2 недели, до позиций.

Правило приоритета: **Индексация → Скорость → Смысл → Разметка → Внешние сигналы.**
Никогда не начинай с текстов, если робот не может дойти до страницы.

## Фаза 0 — Профилирование (обязательно)

Определи и зафиксируй: тип бизнеса (локальный / e-com / SaaS / медиа), гео,
язык, основную поисковую систему (для РФ — **Яндекс первичен**, Google вторичен),
конкурентов в радиусе, и главное конверсионное действие. Всё дальнейшее
взвешивается через это. Локальному барбершопу не нужен hreflang, ему нужны карты.

## Фаза 1 — Технический аудит

| Проверка | Что смотрим | Провал |
|---|---|---|
| Индексация | robots.txt, meta robots, X-Robots-Tag, canonical | страница закрыта или каноникал ведёт не туда |
| Ответы | 200/301/404/5xx, цепочки редиректов | цепочка > 1 хопа |
| Core Web Vitals | LCP, INP, CLS (mobile first) | LCP > 2.5s, CLS > 0.1, INP > 200ms |
| Рендеринг | контент виден без JS? | ключевой текст только после гидратации |
| Дубли | www/non-www, /index.html, слэш, UTM | нет единого каноникала |
| Мобильность | viewport, тап-таргеты ≥ 44px, отсутствие гор. скролла | — |
| Карта сайта | sitemap.xml валиден, все URL 200, есть в robots | — |

Для тяжёлых анимаций (GSAP/Three.js) отдельно проверь: не блокируют ли они LCP.
Правило: **3D-сцена и smooth-scroll грузятся `defer`/`module` и никогда не держат
первый экран.** Текст первого экрана — в HTML, не в JS.

## Фаза 2 — Семантика

1. Собери ядро: базовый спрос + гео-хвосты + вопросные запросы («сколько стоит…»,
   «где…», «можно ли с ребёнком»).
2. Кластеризуй по **интенту**, не по словам: информационный / коммерческий /
   навигационный / транзакционный.
3. Карта релевантности: кластер → URL. Два URL на один кластер = каннибализация, объединяй.
4. Приоритет = (частотность × коммерческость) / сложность. Для локального бизнеса
   низкочастотные гео-запросы дают конверсию выше ВЧ.

## Фаза 3 — On-page

- `<title>`: главный запрос + гео + отличие. До 60 симв. видимой части.
- `<meta description>`: не для ранжирования, а для CTR — цифра, цена или факт внутри.
- `H1` один, повторяет интент, не равен title дословно.
- Иерархия H2/H3 = структура кластера. Каждый H2 отвечает на отдельный вопрос.
- Первые 100 слов содержат: что это, где это, для кого, сколько стоит.
- Внутренние ссылки: анкор описательный, а не «здесь».
- Alt у изображений — описание, а не набор ключей.

## Фаза 4 — Schema.org

Минимум для локального бизнеса — граф `@graph`, а не разрозненные блоки:
`LocalBusiness` (или точный подтип: `HairSalon`, `Restaurant`, `Dentist`) +
`WebSite` + `FAQPage` + `BreadcrumbList` + `OfferCatalog`.

Правила, которые ломают выдачу, если их нарушить:
- `aggregateRating` только из **реальных** агрегированных оценок; выдумал — санкции.
- `Review` дублировать с чужой площадки нельзя; лучше `aggregateRating` + ссылка.
- `priceRange` строкой, `Offer.price` числом без валютного знака + `priceCurrency`.
- FAQ в разметке = FAQ на странице, дословно. Разошлись — разметка невалидна.
- Всегда прогонять через валидатор перед деплоем.

## Фаза 5 — Локальное SEO и карты (для гео-бизнеса — главное)

Для России порядок такой:
1. **Яндекс.Бизнес** — карточка первична, сайт вторичен. Категория, все услуги
   с ценами, фото ≥ 20, режим работы, атрибуты (парковка, Wi-Fi, доступная среда,
   pet-friendly), ответы на все отзывы.
2. **NAP-консистентность**: Название / Адрес / Телефон **посимвольно одинаковы**
   на сайте, в Яндекс.Бизнес, 2ГИС, Google Business Profile, соцсетях.
   Расхождение «14к1» / «14 к. 1» — уже расхождение.
3. На сайте: адрес и телефон текстом (не картинкой), микроразметка `PostalAddress`,
   встроенная карта, схема проезда, район в тексте.
4. **Отзывы** — сильнейший локальный фактор: считай темп (сколько в месяц),
   долю отвеченных (цель 100 %), и упоминания услуг в тексте отзывов —
   это бесплатная семантика, которую надо перенести на сайт.
5. Гео-сетка: проверь позиции карточки из разных точек района, а не из центра города.

## Фаза 6 — GEO / AEO (цитируемость в AI-выдаче)

Новый слой, который большинство игнорирует:
- **Цитируемые пассажи**: каждый ответ на вопрос — самодостаточный абзац на 2–4
  предложения, который можно вырвать из контекста и он останется верным.
- **Факты с числами и датами** — LLM цитируют конкретику, а не «высокое качество».
- **Сущности**: имя бренда, адрес, имена мастеров, названия услуг — писать полно и
  единообразно, чтобы они связывались в граф знаний.
- В `robots.txt` явно разрешить `GPTBot`, `OAI-SearchBot`, `ClaudeBot`, `PerplexityBot`,
  `YandexBot` — если хочешь попадать в ответы.
- Проверка: задать вопрос в AI-поиске и посмотреть, кого цитируют вместо тебя.

## Формат отчёта

```
| # | Проблема | Наблюдение | Влияние | Сложность | Как проверим провал |
```
Сортировка: сначала блокеры индексации, потом CWV, потом смысл.
Максимум 12 пунктов за итерацию — длинный список никто не внедряет.
