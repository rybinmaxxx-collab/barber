# Site Cloner — реверс-инжиниринг живого сайта

## Главный принцип

**Скриншот — это не источник истины. Источник истины — вычисленные стили и код анимаций.**

LLM, который «смотрит на картинку и пишет похожий CSS», всегда даёт ~70% сходства
и застревает. Поэтому мы сначала **измеряем**, кладём измерения в JSON-контракт,
и только потом пишем код из этого контракта. Ни один этап генерации не имеет
права «додумывать» значение, которого нет в контракте.

## Юридический шлюз (выполняется первым, всегда)

Останови работу и спроси пользователя, если ничего из этого не выполняется:
- это его собственный сайт / сайт его клиента;
- это редизайн, где нужно сохранить преемственность;
- копируется **техника** (структура секций, тайминги, кривые), а не бренд.

Никогда не переноси: логотипы, фирменные знаки, фото и иллюстрации, тексты,
платные шрифты. Их место в контракте занимают плейсхолдеры. Скажи это вслух в отчёте.

## Пайплайн: 6 фаз

### Фаза A — Capture (снимаем состояние)
Playwright/Chrome DevTools MCP. Для каждого брейкпоинта (360 / 768 / 1280 / 1920):
1. `page.goto(url, {waitUntil: 'networkidle'})`, дождаться шрифтов: `document.fonts.ready`.
2. Полноэкранный скриншот + серия скроллов 0 / 25 / 50 / 75 / 100 % → `baseline/`.
3. Записать высоты всех секций верхнего уровня → `layout-health.json`.
4. Собрать: HTML после гидратации, список `<link rel=stylesheet>`, инлайн-стили,
   имена JS-бандлов, `<meta name="generator">` (Webflow / Tilda / Framer — важно!).

### Фаза B — Extract (вытаскиваем реальные значения)
Это ядро скилла. Никаких оценок «на глаз».

**Типографика.** Для каждого текстового узла собрать через `getComputedStyle`:
`font-family, font-size, font-weight, line-height, letter-spacing, text-transform`.
Затем — определить реальные файлы шрифтов: `document.fonts` → `family/weight/style`,
и сетевые запросы `.woff2`. Свести к 2–3 семействам + шкале размеров.
Если шрифт коммерческий — найти ближайший свободный аналог и **записать замену в контракт**.

**Цвет и токены.** Собрать все `color / background-color / border-color / box-shadow`
по DOM, отсортировать по частоте → это и есть палитра. Кластеризовать близкие
значения (ΔE < 3) в один токен. Отдельно вытащить `:root` custom properties — если
сайт их использует, палитра уже готова.

**Сетка и ритм.** Ширина контейнера, `padding-inline`, `gap`, число колонок,
брейкпоинты (из `matchMedia` в CSS). Вертикальный ритм — гистограмма
`margin-top/padding-block` секций.

**Анимации — три источника, именно в этом порядке:**
1. **CSS** — распарсить стайлшиты: `transition`, `@keyframes`, `animation-*`,
   `cubic-bezier(...)`, `scroll-timeline`, `view-timeline`.
2. **JS-бандлы** — скачать и грепнуть по сигнатурам:
   - GSAP: `gsap.to(`, `gsap.from(`, `ScrollTrigger.create(`, `scrub`, `pin`, `stagger`, `ease:`
   - Framer Motion: `initial:`, `animate:`, `whileInView`, `type:"spring"`, `stiffness`, `damping`
   - Lenis / Locomotive: `new Lenis(`, `lerp`, `duration`, `smoothWheel`
   - Three.js: `PerspectiveCamera`, `fov`, позиции камеры, интенсивности света
3. **Webflow IX2** (обязательно, если generator = Webflow): вытащить
   `w-mod-*` hide-правила и JSON таймлайнов из `webflow.js` — иначе клон будет с
   «невидимыми» блоками, которые должны появляться по скроллу.
4. **Fallback** — `getComputedStyle` до/после программного триггера
   (hover через `page.hover`, скролл через `scrollTo`), diff двух снимков стилей.

Всё сложить в **один** файл `transition-spec.json` — чтобы не анализировать повторно:

```json
{
  "engine": { "scroll": "lenis", "lerp": 0.09, "duration": 1.05 },
  "tokens": { "brass": "#c9a227", "ink": "#08090b" },
  "type":   { "display": "Oswald 600", "body": "Manrope 400", "scale": [12,14,16,20,28,44,72] },
  "motion": [
    { "sel": ".hero h1 span", "trigger": "load",
      "from": {"yPercent": 115}, "dur": 1.25, "ease": "expo.out", "stagger": 0.09 },
    { "sel": "[data-speed]", "trigger": "scroll",
      "scrub": true, "start": "top bottom", "end": "bottom top", "prop": "yPercent" }
  ]
}
```

### Фаза C — Plan (раскладываем на секции)
Разбить страницу на секции. На каждую — спека: назначение, DOM-скелет, токены,
записи из `motion`, поведение на 4 брейкпоинтах, состояния (hover/focus/open/empty).
Спека — это ТЗ для генерации; секции независимы и могут строиться параллельно.

### Фаза D — Build (пишем код)
Целевой стек задаёт пользователь (React+Tailwind / Astro / чистый HTML+CSS).
Правила: только значения из контракта; токены — в CSS-переменные или `theme`;
анимации — тем же движком, что в оригинале (GSAP → GSAP), иначе кривые «поплывут»;
`prefers-reduced-motion` обязателен даже если у оригинала его нет.

### Фаза E — Verify (машинная проверка, не глазами)
1. Снять те же скриншоты клона, что и в фазе A.
2. Посчитать **SSIM** и **AE** попарно. Порог: SSIM ≥ 0.92 по секции.
3. `layout-health`: сравнить высоты секций — расхождение > 12 % значит «сломан ритм»,
   а не «другой оттенок».
4. Проверить моушен: записать по 30 кадров скролла у оригинала и клона,
   сравнить кривую перемещения элемента — сходство таймингов важнее сходства пикселей.
5. **Vision-модель подключается только если авто-проверка не прошла** — и получает
   один diff-кадр, а не всю галерею. Так расходуется в разы меньше токенов.

### Фаза F — Heal (самоисправление)
До 3 итераций: худшая секция по SSIM → уточнить её спеку → перегенерировать →
перепроверить. После 3 итераций — стоп, отчёт `failed_with_residuals` со списком того,
что не сошлось и почему. Молча отдавать неготовое нельзя.

## Два финальных состояния

- `ready_for_user_review` — все секции ≥ порога, моушен совпадает, отчёт приложен.
- `failed_with_residuals` — перечислить остатки: секция, метрика, гипотеза причины.

Третьего («вроде похоже») не существует.

## Артефакты на выходе

```
clone/
  baseline/          скриншоты оригинала
  candidate/         скриншоты клона
  transition-spec.json
  sections/*.md      спеки секций
  report.md          SSIM/AE таблица + что заменено плейсхолдерами
```
