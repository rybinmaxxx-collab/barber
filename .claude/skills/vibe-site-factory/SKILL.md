# Vibe Site Factory — конвейер сайтов

Оркестратор. Сам почти ничего не делает — вызывает три скилла в жёстком порядке
и следит, чтобы ни один этап не начался без артефакта предыдущего.

Отвечает за **скорость**. За **предсказуемость** отвечает скилл `gated-delivery`:
он решает, когда этому конвейеру можно стартовать и что уже утверждено.
Если решения по движению и палитре ещё не зафиксированы кодами — сначала он.

```
   RECON ──► CONTEXT ──► REFERENCE ──► DESIGN ──► BUILD ──► SEO ──► SHIP
 (данные)  (growth-    (site-cloner)  (токены)  (код)   (super-  (deploy)
            agency)                                       seo)
```

**Железное правило конвейера: контент раньше кода.** Пока не заполнен
`brand-context.md` реальными фактами, писать HTML запрещено — иначе получится
красивый шаблон с текстом «Мы — команда профессионалов».

## Этап 0 · RECON — разведка (10 мин)

Вход: что угодно — ссылка на карточку в Яндекс/Google Картах, домен, скриншот, имя.

Собрать и записать в `research.md` **только проверяемые** факты:

- название (точное написание, включая кавычки и регистр), категория;
- адрес посимвольно + район/ориентир, координаты;
- телефон в формате `+7XXXXXXXXXX` (для `tel:`) и в человеческом;
- рейтинг, число оценок, число отзывов, награды площадки;
- прайс — все позиции, которые опубликованы;
- атрибуты: парковка, Wi-Fi, оплата, доступная среда, животные, запись;
- **цитаты из отзывов** — это готовые заголовки и готовый FAQ;
- имена сотрудников, если они звучат в отзывах;
- 2–3 конкурента в радиусе и чем они хуже.

Чего **нельзя** делать: придумывать часы работы, цены, отзывы, имена, «10 лет опыта».
Неизвестное поле помечается `TODO(владелец)` и попадает в финальный список вопросов.

## Этап 1 · CONTEXT — упаковка (10 мин) → скилл `growth-agency`

Из `research.md` собрать `brand-context.md`, затем прогнать совет ролей и получить:
позиционирование, оффер, структуру секций, все тексты, главное действие,
6 вопросов FAQ из реальных возражений.

Выход: `copy.md`. Это ТЗ на вёрстку. Дальше тексты не сочиняются.

## Этап 2 · REFERENCE — эталон движения (10 мин) → скилл `site-cloner`

Нужен, только если есть референс («хочу как на awwwards-сайте X»).
Забираем **технику, не бренд**: тайминги, кривые, тип скролла, набор триггеров.
Выход: `transition-spec.json`. Если референса нет — берём базовый пресет ниже.

### Базовый пресет движения (проверенный, безопасный)

```js
scroll : Lenis { lerp: 0.09, duration: 1.05 }
enter  : y +38px, opacity 0→1, 0.9s, cubic-bezier(.22,1,.36,1), stagger 0.09
hero   : построчный маскированный выезд yPercent 115→0, 1.25s, expo.out
parallax: data-speed 0.8–0.9, scrub: true
horizontal: лента едет по X от вертикального скролла, scrub 0.8
hover  : tilt ±14°, длительность 0.35s, + радиальный блик за курсором
cursor : кастомный, lerp 0.16, mix-blend-mode: difference
```

## Этап 3 · DESIGN — токены (5 мин)

Один экран решений, дальше не обсуждается:
палитра (фон / текст / 1 акцент / 1 второй акцент), 2 шрифта
(дисплейный узкий + читаемый гротеск, **обязательно с кириллицей**),
шкала размеров, радиусы, единый `--ease`, единый `--pad`.
Всё — в `:root`. Ни одного хардкод-цвета в разметке.

Проверка кириллицы: Bebas Neue, Anton, Playfair — **нет кириллицы**.
Безопасно: Oswald, Manrope, Inter, Montserrat, PT Sans, Golos, Unbounded.

## Этап 4 · BUILD — сборка (20 мин)

Порядок строго такой, потому что каждый шаг проверяем в браузере:

1. Скелет HTML со **всем текстом** из `copy.md` — без единого стиля.
   На этом шаге сайт уже должен быть полезен: адрес, цены, телефон видны.
2. Токены + типографика + сетка.
3. Секции сверху вниз.
4. Слой движения (`main.js`): reveal → параллакс → горизонт → курсор → tilt.
5. 3D-сцена (`scene.js`) — **последней и отдельным модулем**. Она обязана
   деградировать: нет WebGL → градиент, `prefers-reduced-motion` → почти статика,
   вкладка скрыта → рендер останавливается.
6. Мобильный док с главным действием.

### Бюджеты, которые нельзя превышать
- Первый экран читаем **без** JS.
- LCP ≤ 2.5 с на 4G, CLS ≤ 0.1.
- Ни одна анимация не блокирует ввод; всё тяжёлое — `defer` / `type=module`.
- `prefers-reduced-motion: reduce` выключает моушен, а не ломает вёрстку.

## Этап 5 · SEO (10 мин) → скилл `super-seo`

`title`/`description`/`canonical`/OG/Twitter, `@graph` с точным подтипом
(`HairSalon`, `Restaurant`, `Dentist`…), `FAQPage` **дословно** как на странице,
`OfferCatalog` с реальными ценами, `aggregateRating` **только из реальных оценок**,
`robots.txt` с разрешением AI-краулеров, `sitemap.xml`, `manifest`, `lang="ru"`.

## Этап 6 · SHIP (5 мин)

Деплой (GitHub Pages / Vercel / Netlify), проверка на реальном мобильном,
валидатор микроразметки, Lighthouse. В отчёт — список `TODO(владелец)`:
что нужно получить от клиента (фото, часы, цены на бороду, домен).

## Definition of Done

- [ ] Все факты на сайте проверяемы, выдумок ноль
- [ ] Телефон кликабелен, адрес текстом, карта встроена
- [ ] Главное действие видно на любом экране без скролла
- [ ] Работает без WebGL и без JS-анимаций
- [ ] Микроразметка проходит валидатор
- [ ] Lighthouse: Perf ≥ 85 (mobile), SEO = 100, A11y ≥ 90
- [ ] Список открытых вопросов владельцу приложен

## Что чаще всего ломается

| Симптом | Причина | Лечение |
|---|---|---|
| Заголовки латиницей норм, кириллица — дефолт | шрифт без кириллицы | сменить семейство, не «поправить fallback» |
| Секции прыгают при скролле | ScrollTrigger посчитал до загрузки шрифтов | `ScrollTrigger.refresh()` после `document.fonts.ready` |
| На телефоне низкий FPS | много частиц + большой pixelRatio | `min(devicePixelRatio, 2)`, меньше частиц на мобиле |
| Горизонтальная лента едет мимо | ширина считается один раз | `invalidateOnRefresh: true` и функции вместо чисел |
| Пустой первый экран у робота | текст рисует JS | текст в HTML, анимация только скрывает/показывает |
